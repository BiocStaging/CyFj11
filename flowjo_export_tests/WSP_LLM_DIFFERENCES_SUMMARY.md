# FlowJo .wsp vs .llm.wsp comparison summary

## Context

For each `flowjo_export_tests/testNN` directory there are two workspace files:

- `testNN_export.wsp` — original workspace exported by the CyFJ11 R package.
- `testNN_export.llm.wsp` — the same workspace after it was opened and re-saved in FlowJo 10.10.1.

This document summarizes the differences between the two versions across all 14 tests.

Two comparison scripts were used and are kept in the repository root for reproducibility:

- `compare_wsp.py` — XML-structural diff (added/removed/changed nodes by path).
- `compare_wsp_semantic.py` — semantic diff focused on transformations, population counts, and file URIs.

Both scripts write their detailed reports to:

- `flowjo_export_tests/wsp_comparison_report.md`
- `flowjo_export_tests/wsp_semantic_comparison_report.md`

---

## Method

1. Listed all `flowjo_export_tests/test*` directories.
2. For each test, parsed both `.wsp` and `.llm.wsp` with Python `xml.etree.ElementTree`.
3. Compared:
   - Workspace metadata (`modDate`, `clientTimestamp`, file path).
   - Data file URIs.
   - Per-channel transformation definitions.
   - Population/gating hierarchy (names, counts, gate IDs).
   - XML structure (added/removed nodes and changed attributes).
4. Verified suspicious cases (test13, test14, test07, test12) by direct inspection of the XML.

| Aspect | Original `.wsp` | After FlowJo save `.llm.wsp` | Impact |

| **File metadata** | `clientTimestamp="NA"`, `modDate` from R export | Real timestamp and save date | Cosmetic |

## Detailed findings

### 1. Data file URI

Every test except test14 has the original URI pointing to an R temporary directory and the LLM version pointing to the local `.fcs` file inside the test directory. test14 already had a local path in the original.

Example (test01):

- Original: `file:/pasteur/helix/scratch/bernd/Rtmp/Rtmpel7rVw/file3002afd4edec0/sample01.fcs`
- LLM: `file:/System/Volumes/Data/pasteur/helix/projects/scBiomarkers/bernd/cytometry/CyFj11/flowjo_export_tests/test01/sample01.fcs`

This is expected behavior when FlowJo resolves sample links on a new machine.

### 2. Transformations

Across tests 01–09 and 11–13, fluorescence parameters were converted from their original transformation to `log` with `offset="1"` and `decades` around 4. The exact value is data-dependent.

- **test01**: `FITC-A`, `PE-A`, `APC-A`, `PerCP-Cy5-5-A` become `log`.
- **test06, 11, 12**: `FITC-A` was originally `biex` with `length="4096"`; FlowJo keeps `biex` but changes `length` to `"256"`.
- **test08, 11, 13**: `APC-A` (and in test13 also `FITC-A`/`PE-A`) was originally `fasinh` with `M="4"`, `length="1"`, `W="-262144"`; FlowJo changes to `M="5.418539922"`, `length="256"`, `W="-262144.0000000001"`.
- **test14**: All scatter parameters keep `linear`; a `Time` transformation is added. Cytometer is changed to BD DIVA.

These changes are not merely cosmetic: they affect how the data is scaled and displayed, which can change gate boundaries and population counts if FlowJo recomputes gates.

### 3. Population count issues

Direct XML inspection confirmed that several tests suffer from real population-count changes after re-saving:

- **test07**: `/PE_pos` drops from **3,198 to 753**.
- **test12**: `/cells/PE_hi` drops from **3,831 to 2,143**.
- **test13**: `/live/FITC_PE_gate` jumps from **2,983 to 9,940**, essentially matching the parent count (gate no longer filters).
- **test14**: All terminal populations below `Singlets2` become **0 cells**. Only the top three nodes keep non-zero counts:
  - `Lymphocytes`: 19,225 → 19,203
  - `Singlets`: 18,702 → 18,680
  - `Singlets2`: 18,585 → 18,563
  - Everything else (NK cells, B cells, T-cell subsets, etc.): **0**

### 4. Gate IDs and rendering

FlowJo regenerates all Gating-ML gate IDs. In addition:

- `lineWeight="1"` becomes `lineWeight="Hairline"`.
- `percentX`/`percentY` attributes are often dropped or reset.
- `quadId` is set to `"-1"` and `gateResolution` to `"256"` for `PolygonGate`.

These are normal serialization artifacts and do not change gating logic.

### 5. Structural XML changes

- Empty `<Subpopulations>` nodes are removed.
- `<Graph>` subtrees are added under population nodes (for group-level plotting).
- `<TableEditor>` / `<LayoutEditor>` get default output files and titles reflecting the saved workspace name.
- `<PlateEditorState>` keyword order is reshuffled by FlowJo.
- `<WindowPosition>` dimensions changed in test13 (likely from window resize).

---

## Recommendations

1. **test14 is unusable after FlowJo save** — all subset counts are zero. Investigate why FlowJo cannot resolve the sample/transform/cytometer combination. The cytometer change from `GENERIC` to `DIVA` is the most suspicious difference.
2. **test13 gate `FITC_PE_gate` is broken** — its count equals the parent, indicating the gate was not applied or could not be evaluated. This may be related to the `fasinh` → `log`/modified `fasinh` transformation change.
3. **test07 and test12 show large count drops** — verify whether the gates still contain the intended cells or whether the transformation conversion shifted the gate boundaries.
4. **Transformation conversion is systematic** — if the package intends to preserve `biex`/`fasinh` settings, the exported workspace may need to embed the same defaults FlowJo expects, or the export should be validated against FlowJo's native serialization.
5. **File URI rewriting is expected** — the package does not need to fix this, but tests should be robust to path changes when comparing workspaces.
